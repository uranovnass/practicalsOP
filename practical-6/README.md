## 2. Цель работы

Изучить механизмы синхронизации потоков, исследовать возникновение гонок данных и способы их устранения. Реализовать задачу «производитель–потребитель» с использованием семафоров, мьютекса и условной переменной, создать барьер для синхронизации потоков и продемонстрировать проблему потерянного пробуждения.

## 3. Теоретические сведения

### 3.1. Гонка данных

Гонка данных возникает, когда несколько потоков одновременно обращаются к общим данным и хотя бы один из них изменяет их без необходимой синхронизации. Это может привести к потере обновлений и некорректным результатам.

### 3.2. Мьютекс

Мьютекс обеспечивает взаимное исключение при работе с общими ресурсами. В Python для этого используется `threading.Lock()`. Конструкция `with lock:` автоматически освобождает блокировку после завершения защищённого участка кода.

### 3.3. Семафор

Семафор контролирует количество потоков, которые могут получить доступ к ограниченному ресурсу. В данной работе используются два семафора:

- `empty` — количество свободных ячеек буфера;
- `full` — количество занятых ячеек буфера.

### 3.4. Условная переменная

Условная переменная позволяет потоку ожидать изменения состояния общего ресурса. В Python используется `threading.Condition()`. Метод `wait()` временно освобождает блокировку и при пробуждении повторно захватывает её. Метод `notify_all()` уведомляет ожидающие потоки.

Условие ожидания необходимо проверять в цикле `while`, поскольку пробуждение не гарантирует, что требуемое условие всё ещё выполняется.

### 3.5. Кольцевой буфер

Кольцевой буфер — структура данных фиксированной ёмкости, в которой после последней ячейки индекс возвращается к началу.

Для перехода между ячейками используется операция:

`index = (index + 1) % CAPACITY`

В этой работе ёмкость буфера составляет 5 элементов.

### 3.6. Барьер

Барьер — механизм синхронизации, который задерживает потоки до момента, когда все участники достигнут определённой точки выполнения. После этого все потоки могут перейти к следующей фазе.

### 3.7. Потерянное пробуждение

Потерянное пробуждение возникает, когда поток отправляет уведомление до того, как другой поток начал ожидание. Если проверка условия и вызов `wait()` не синхронизированы общей блокировкой, уведомление может быть пропущено.

## 5. Описание программ

### 5.1. `race_condition.py`

Демонстрирует гонку данных при параллельном увеличении общей переменной.

Параметры эксперимента:
- количество потоков: 4;
- количество операций на поток: 10 000;
- ожидаемое значение счётчика: 40 000.

Из-за отсутствия синхронизации итоговое значение может отличаться от ожидаемого.

### 5.2. `race_condition_fixed.py`

Исправленная версия предыдущей программы. Для защиты общей переменной используется `threading.Lock()`.

Корректность проверяется сравнением фактического и ожидаемого значений с помощью `assert`.

Ожидаемый результат: `40000`.

### 5.3. `producer_consumer_semaphore.py`

Реализует задачу «производитель–потребитель» с кольцевым буфером на основе двух семафоров и мьютекса.

Параметры:
- размер буфера: 5 элементов;
- количество производителей: 3;
- количество потребителей: 2;
- общее количество производимых элементов: 1000.

Семафор `empty` ограничивает добавление элементов при заполненном буфере, а `full` не позволяет потребителям извлекать элементы из пустого буфера. Мьютекс защищает общие индексы, счётчик заполнения и операции с буфером.

Для завершения потребителей после производства всех элементов используются специальные сигналы завершения.

### 5.4. `producer_consumer_condition.py`

Реализует ту же задачу с использованием `threading.Condition()` вместо семафоров.

Производители ожидают освобождения места, а потребители — появления элементов. После изменения состояния буфера потоки уведомляются с помощью `notify_all()`.

Условия ожидания проверяются в циклах `while`.

### 5.5. `synchronization_demo.py`

Демонстрирует реализацию барьера на условной переменной для четырёх потоков, работающих в три фазы.

Для синхронизации используются:
- `threading.Condition()`;
- счётчик достигших барьера потоков;
- номер текущего поколения барьера.

Переход к следующей фазе разрешается только после достижения барьера всеми четырьмя потоками.

### 5.6. `lost_wakeup.py`

Демонстрирует потерянное пробуждение. Проверка условия выполняется до захвата блокировки, что позволяет отправить уведомление раньше, чем ожидающий поток вызовет `wait()`.

В примере используется тайм-аут, чтобы демонстрация не приводила к бесконечному ожиданию.

## 6. Проверка корректности

В обеих реализациях задачи «производитель–потребитель» проверяются следующие инварианты:

1. Потреблено ровно 1000 элементов.
2. Каждый элемент потреблён ровно один раз.
3. Отсутствуют пропущенные элементы.
4. Максимальное заполнение буфера не превышает его ёмкость.
5. После завершения работы буфер пуст.
6. Отсутствуют зарегистрированные нарушения.

Для автоматической проверки используются `collections.Counter`, сравнение множеств, подсчёт элементов и инструкции `assert`.

Ожидаемые показатели:

| Показатель | Ожидаемое значение |
|---|---:|
| Произведено элементов | 1000 |
| Потреблено элементов | 1000 |
| Уникальных элементов | 1000 |
| Пропущенных элементов | 0 |
| Повторяющихся элементов | 0 |
| Ошибок | 0 |
| Максимальное заполнение буфера | Не более 5 |

Фактическое максимальное заполнение буфера может быть меньше 5 — это не является ошибкой.

## 7. Требования и ограничения реализации

- Используется многопоточность на основе модуля `threading`.
- Для задачи «производитель–потребитель» не применяется `queue.Queue`.
- Общие данные защищаются механизмами синхронизации.
- Блокировки используются через контекстный менеджер `with`.
- Условия ожидания проверяются в циклах `while`.
- Корректность подтверждается программными проверками, а не только визуальным анализом вывода.

## 9. Контрольные вопросы

### 1. Чем семафор со значением 1 отличается от мьютекса на практике?

Семафор со значением 1 ограничивает количество потоков, одновременно получающих доступ к ресурсу, одним потоком. Мьютекс предназначен для взаимного исключения и обычно имеет понятие владельца блокировки.

В Python `threading.Lock` и `threading.Semaphore(1)` не полностью взаимозаменяемы: они различаются семантикой и правилами использования.

### 2. Почему условную переменную нельзя использовать без мьютекса?

Мьютекс защищает общее состояние и позволяет согласовать проверку условия с переходом к ожиданию. В Python `threading.Condition` уже включает блокировку, поэтому обычно используется конструкция `with condition:`.

Без правильной синхронизации между проверкой условия и ожиданием возможно потерянное уведомление, а также некорректная работа потоков.
