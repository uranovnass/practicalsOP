## 4. Теоретические сведения

### 4.1. Взаимоблокировка

Deadlock — это ситуация, при которой несколько процессов или потоков бесконечно ожидают ресурсы, удерживаемые друг другом.

Четыре необходимых условия возникновения взаимоблокировки:

1. **Взаимное исключение:** ресурс одновременно используется только одним процессом.
2. **Удержание и ожидание:** процесс удерживает один ресурс и ожидает другой.
3. **Отсутствие принудительного освобождения:** ресурс нельзя принудительно забрать у процесса.
4. **Циклическое ожидание:** существует замкнутая цепочка процессов, ожидающих ресурсы друг друга.

### 4.2. Алгоритм банкира

Алгоритм банкира проверяет, останется ли система в безопасном состоянии после выдачи ресурсов.

Основные структуры:

- `Available` — количество доступных ресурсов каждого типа.
- `Allocation` — количество ресурсов, выделенных каждому процессу.
- `Max` — максимальная потребность каждого процесса.
- `Need` — оставшаяся потребность процесса.

Формула:

`Need = Max - Allocation`

Состояние считается безопасным, если существует последовательность, в которой каждый процесс может получить необходимые ресурсы, завершиться и вернуть выделенные ресурсы системе.

При обработке запроса программа:

1. Проверяет корректность номера процесса и вектора запроса.
2. Проверяет, не превышает ли запрос оставшуюся потребность.
3. Проверяет наличие достаточного количества ресурсов.
4. Временно выделяет ресурсы.
5. Проверяет безопасность нового состояния.
6. Подтверждает запрос или выполняет откат.

### 4.3. Граф ожидания

Граф ожидания представляет отношения между потоками.

Если поток `T1` ожидает ресурс, удерживаемый потоком `T2`, в граф добавляется ребро `T1 → T2`.

Цикл в графе ожидания указывает на взаимоблокировку при условии, что рассматриваются корректные зависимости между потоками и ресурсы имеют единичные экземпляры.

### 4.4. Предотвращение взаимоблокировок

В работе рассматриваются два подхода:

- **Глобальный порядок захвата ресурсов:** ресурсы захватываются в установленной последовательности.
- **Ограничение числа участников:** одновременно к ресурсам допускается не более четырёх из пяти философов.

Оба подхода позволяют предотвратить взаимоблокировку в рассматриваемых сценариях.

## 6. Запуск и проверка программ

### 6.1. Алгоритм банкира

Проверка безопасного состояния:

```bash
python3 banker.py bank1.txt
```

Ожидаемый результат:

```text
Файл: bank1.txt
Available: [3, 3, 2]
Состояние: БЕЗОПАСНОЕ
Безопасная последовательность: P1 -> P3 -> P4 -> P0 -> P2
```

Проверка небезопасного состояния:

```bash
python3 banker.py bank2.txt
```

Ожидаемый результат:

```text
Файл: bank2.txt
Available: [0, 1, 0]
Состояние: НЕБЕЗОПАСНОЕ
Безопасная последовательность не найдена.
```

После проверки программа ожидает запросы ресурсов в интерактивном режиме.

Формат ввода:

```text
PID ресурс1 ресурс2 ресурс3
```

Пример запроса:

```text
1 1 0 0
```

Здесь `1` — номер процесса P1, а `1 0 0` — запрашиваемый вектор ресурсов.

Для выхода из интерактивного режима введите:

```text
exit
```

Программа должна отклонять некорректные запросы, запросы сверх `Need` и запросы, после которых состояние становится небезопасным. При отклонении по небезопасности исходное состояние восстанавливается.

### 6.2. Обнаружение взаимоблокировки в журнале

Запуск:

```bash
python3 detector.py events.txt
```

Журнал содержит события захвата ресурсов и ожидания:

```text
acquire T1 A
acquire T2 B
wait T1 B
wait T2 A
```

Ожидаемый результат включает цикл:

```text
ОБНАРУЖЕН DEADLOCK!
Цикл: T1 -> T2 -> T1
Участники: T1, T2
```

Порядок вывода потоков может отличаться. Важно, чтобы программа обнаруживала цикл и выводила его участников.

### 6.3. Проверка TrackedLock

Запуск:

```bash
python3 tracked_lock_test.py
```

Программа создаёт два потока и две блокировки. Каждый поток захватывает одну блокировку, после чего пытается получить вторую.

Ожидаемое поведение:

- обнаруживается цикл ожидания;
- возникает исключение `DeadlockDetected`;
- потоки освобождают принадлежащие им блокировки;
- программа завершается без бесконечного ожидания.

### 6.4. Демонстрация deadlock.py

Запуск:

```bash
python3 deadlock.py
```

Ожидаемый вывод содержит сообщения о захвате блокировок A и B и ожидании блокировок, занятых другим потоком.

Программа намеренно зависает, поскольку потоки удерживают разные блокировки и ждут друг друга.

Для остановки нажмите:

```text
Ctrl + C
```

Зависание является ожидаемым результатом эксперимента, а не свидетельством успешного завершения программы.

### 6.5. Задача обедающих философов

Запуск:

```bash
python3 philosophers.py
```

Программа проверяет два исправленных режима:

1. Захват вилок в порядке возрастания номеров.
2. Ограничение числа одновременно допущенных философов с помощью семафора.

Для каждого режима выводится число приёмов пищи каждого философа и общая статистика.

При `ROUNDS = 100` ожидается 100 приёмов пищи на каждого философа и 500 в сумме для каждого исправленного режима.

Исходный небезопасный сценарий демонстрируется отдельно в `deadlock.py`.

## 9. Контрольные вопросы

### 1. Почему упорядочивание захвата ресурсов исключает deadlock?

Если все потоки захватывают ресурсы в одном глобальном порядке, например сначала ресурс с меньшим номером, а затем с большим, циклическое ожидание невозможно. Следовательно, нарушается одно из необходимых условий возникновения deadlock.

### 2. Почему алгоритм банкира редко применяется в универсальных операционных системах?

Алгоритм требует заранее знать максимальную потребность каждого процесса и проверять безопасность при запросах ресурсов. В универсальных операционных системах потребности процессов динамичны, а некоторые ресурсы сложно заранее описать и распределить по такой модели.
