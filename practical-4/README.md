# Практическая работа №4 — Потоки в Linux

## Цель работы

Изучить работу потоков и процессов в Linux, а также сравнить их производительность при выполнении CPU- и сетевых задач.

В работе сравниваются три подхода:

* последовательное выполнение;
* выполнение с использованием 4 потоков;
* выполнение с использованием 4 процессов.

Также проверяется общая память потоков и процессов.

---

## Структура проекта

```text
practical-4/
├── practical4.py
├── numbers.txt
└── README.md
```

## Описание работы

Программа выполняет две задачи.

### 1. CPU-задача

Из файла `numbers.txt` загружается 10 000 000 чисел.

Затем вычисляется их сумма тремя способами:

1. последовательно;
2. с использованием 4 потоков;
3. с использованием 4 процессов.

Правильная сумма:

```text
50000005000000
```

Все три способа получили правильный результат.

### 2. Сетевая задача

Создаётся локальный сервер, с которого программа загружает 20 файлов.

Загрузка выполняется:

1. последовательно;
2. с использованием 4 потоков;
3. с использованием 4 процессов.

Для каждого варианта выполняется 3 запуска, после чего рассчитывается медианное время.

---

## Результаты CPU-задачи

| Метод           | Запуск 1 | Запуск 2 | Запуск 3 |      Медиана |
| --------------- | -------: | -------: | -------: | -----------: |
| Последовательно | 0.2965 с | 0.2730 с | 0.2900 с | **0.2900 с** |
| 4 потока        | 0.5892 с | 0.5844 с | 0.5851 с | **0.5851 с** |
| 4 процесса      | 1.9961 с | 1.9142 с | 1.8607 с | **1.9142 с** |

### Вывод по CPU-задаче

В данной программе последовательное выполнение оказалось самым быстрым.

4 потока работали примерно в 2 раза медленнее, а 4 процесса — ещё медленнее.

Это связано с тем, что работа выполняется на Python, а создание и управление потоками и процессами добавляет дополнительные расходы.

---

## Результаты сетевой задачи

| Метод           | Запуск 1 | Запуск 2 | Запуск 3 |      Медиана |
| --------------- | -------: | -------: | -------: | -----------: |
| Последовательно | 0.0601 с | 0.0343 с | 0.0356 с | **0.0356 с** |
| 4 потока        | 0.0388 с | 0.0362 с | 0.0370 с | **0.0370 с** |
| 4 процесса      | 0.0688 с | 0.0649 с | 0.0682 с | **0.0682 с** |

### Вывод по сетевой задаче

Для сетевой задачи последовательный вариант и вариант с потоками показали близкие результаты.

Потоки подходят для сетевых задач, потому что во время ожидания ответа одного соединения другой поток может выполнять другую работу.

В данной конкретной локальной проверке преимущество потоков получилось небольшим, потому что сервер находится на том же компьютере.

Использование процессов оказалось самым медленным из-за дополнительных затрат на создание и управление процессами.

---

## Проверка общей памяти

В программе также проверяется изменение общего списка.

Получен результат:

```text
После потока: ['parent', 'thread']
После процесса: ['parent', 'thread']
```

Потоки используют общую память одного процесса, поэтому изменения списка видны основному потоку.

Процессы имеют отдельные адресные пространства, поэтому изменения обычных переменных внутри дочернего процесса не должны автоматически передаваться родительскому процессу.

✓ Результат процессов правильный

Итоговая правильная сумма:

## Общий вывод

В ходе практической работы были сравнены последовательное выполнение, потоки и процессы.

Для данной CPU-задачи самым быстрым оказался последовательный вариант:

```text
0.2900 сек.
```

Для сетевой задачи результаты последовательного выполнения и потоков оказались очень близкими:

```text
Последовательно — 0.0356 сек.
4 потока — 0.0370 сек.
```

Таким образом, выбор между потоками и процессами зависит от типа задачи. Потоки особенно полезны для задач, связанных с ожиданием ввода-вывода, например сетевых запросов. Процессы позволяют выполнять вычисления независимо друг от друга, но создание процессов требует дополнительных ресурсов.
